## 沙箱竞价规则

- 申请方只能为自己已批准的资料创建投放，选择经营品牌；城市固定为审核后的资料城市。
- 按匹配品牌/城市、公开状态、投放状态、期限及剩余预算筛选，再按单次联系入口出价降序；同价按创建时间及 ID 稳定排序。展示明确标注“推广 · 沙箱”。
- 原型采用联系入口模拟消耗：电话查看或微信联系触发。同一访客对同一推广在同一 UTC 自然日最多消耗一次；本人预览不记录或消耗。普通曝光、浏览和预约提交不消耗此预算。
- 用户创建前明确确认总模拟预算、出价和周期。当前可测试范围：出价 0.01–100 元，预算不少于出价且不超过 10 万元，期限 1–30 天；这些范围是开发原型配置，不是已确定的正式商业报价。
- 可暂停、恢复；到期、下线、资料不匹配或预算不足时不再推广。恢复时重新核验。
- 投放消耗只写入 partner_campaigns / partner_spend，不计入品牌 merchant_categories / rank_ledger。并发联系在事务内锁定预算，流水禁止更改或删除，申请、投放和预约支持幂等重试。
- 正式环境禁止创建沙箱投放，尚无真实支付、充值、提现或生产扣费。

## 数据与 API

新增迁移：apps/api/migrations/008_partner_market.sql。
新增服务：apps/api/src/partners.ts。

公开/本人 API：

- GET /partners/brand/:brandId?city=城市：公开资料，联系方式在用户主动操作后返回；不公开所有者标识。
- GET /partners/mine：仅当前匿名 Cookie 身份的资料、指标、预约与投放，禁止缓存。
- POST /partners/apply：幂等新申请，使用 Idempotency-Key。
- POST /partners/:id/revisions：本人修订，重复相同待审内容返回同一修订。
- POST /partners/:id/events：联系及浏览事件，不允许客户端伪造 APPOINTMENT。
- POST /partners/:id/appointments：明确同意后向指定门店/销售提供称呼、电话、时间及备注，幂等提交。
- POST /partners/appointments/:id/state：仅资料所有者处理预约。
- POST /partners/campaigns：确认后的沙箱推广，使用 Idempotency-Key。
- POST /partners/campaigns/:id/state：仅所有者暂停/恢复。

平台 API：

- GET /admin/partners 与 POST /admin/partners/:id/review、/visibility：管理员或审核员。
- GET /admin/partner-analytics：仅管理员，包括全站联系、投放和预约。
- 新增写接口均使用当前会话/访客 CSRF 校验；审核要求版本号与处理依据，官方/授权标识另需核验依据。
