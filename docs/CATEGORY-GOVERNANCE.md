# 品牌首次归类：先展示、后审核

日期：2026-10-27。用户补充“首次用户打款了先展示，然后平台后审核”，覆盖先审核再进入品类榜的中间方案。

## 当前规则

每个品牌使用一个主品类。平台已确认的品类直接沿用；尚未设置的品牌，仅首次成功助力时保存建议。打开表单、创建未付款订单不会预占品类。首次成功到账后立即展示总榜和建议品类榜，并标记“待核实”。后续助力自动沿用暂定或确认后的主品类，不再逐笔选类，也不能通过改请求参数投到其他品类。

两个访客并发首次付款，事务锁保证只保留一项初始建议。此前已创建的其他未付款订单仍可完成，但不会覆盖已经建立的归属，回执显示实际归属。

“先展示”意味着暂定期间仍可能出现短期错类。唯一已发布平台品类可直接采用；跨品类图鉴不擅自挑选主品类，需要首次建议或平台指定。未核实和历史归类在后台集中处理。

## 错填与恶意分类的处理

- 助力表单及品牌详情提供“品类有误？提交纠错”，填写正确品类与至少5字依据。
- 纠错只产生报告，不能直接改归属；同一匿名访客对同一品牌只保留一条未处理报告，可补充依据。
- 每个匿名访客每小时最多新增10条纠错报告。此为基础限频，清除Cookie可绕过，正式反滥用仍需结合登录与服务端风控。
- 后台“品牌归类”支持待核实、有纠错及全部品牌筛选。ADMIN/REVIEWER可根据依据确认或纠正品类，USER/EDITOR无权审核。
- 每次平台处理必须提供依据，并检查版本防止旧页面覆盖新修改；保存审核人、前后归属、理由、时间与版本，同时记录审计并处理当前未关闭的纠错。
- 不以举报数量自动改类，不允许付款者反复切换品牌归属。明显异常品牌仍可使用已有展示管理进行隐藏。

## 金额与迁移

006迁移新增 brand_classifications、brand_category_reports、brand_category_history。品牌归类独立于付款账本，品类榜按暂定/确认主品类汇总该品牌的全部有效金额。平台纠正后，金额从旧品类榜展示转到正确品类榜；订单、支付回执、不可变流水和总榜金额不修改，不重复入账、不新增虚假到账动效。

新付款订单会沿用当前主品类。历史订单页面明确显示下单时品类，保留原记录。总榜霸榜计时不因纯归类修改重置；品类榜按实际归属重算榜首。到账特效也按当前归属筛选。

历史已有资金但没有平台唯一品类的品牌，保留现有记录为暂定建议并进入待核实列表；不删除资金或自动将模糊归属标成平台已确认。图鉴中同品牌跨品类的编辑资料保留，助力主品类由本规则独立维护。

## 接口

- public/brands、品牌资料及 merchants/:id 返回 classification：state（UNSET/PENDING/CONFIRMED）、categoryId/Name、suggestedCategoryId/Name、version、source。
- POST /support/orders：merchantId、amountFen；仅未设置时需要 categoryId。已固定时如仍传入其他品类则409。
- POST /sandbox/orders/:id/pay：补充返回实际 classification；重复支付不重复设置品类。
- POST /public/brands/:id/category-report：categoryId、reason，要求访客CSRF或管理会话CSRF。
- GET /admin/brand-categories：归类队列、纠错与修改记录；不返回匿名访客标识。
- POST /admin/brand-categories/:id：categoryId、version、reason，仅平台ADMIN/REVIEWER。
