# Flutter 页面、交互与视觉规格

## 1. 全局信息架构

底部四项：发现 / 品类 / 商家榜 / 我的。品牌对比是浮动操作和独立页，不额外占底部标签。
首页内容依次为搜索框、近期选择品类、编辑推荐品牌对比、场合专题、商家入口。
品类页是大品类网格，不出现层层展开的树。

用户核心路径：
打开 → 选“电脑” → 品牌地位榜 → 品牌详情 → 加入对比 → 返回比较 → 看电脑商家累计榜 → 商家详情 → 店铺或直播。

商家路径：
某品类商家榜 → 我要打榜 → 品牌名 + Logo + 金额 → 登录/付款 → 上榜。
上榜后可进入商家中心补充介绍、店铺、直播；这些选填项不阻断核心路径。
App 中根据渠道能力显示管理能力；支付入口仅在受支持且审核允许的环境出现。

## 2. 页面与路由

| 页面 | 路由 | 主元素与关键状态 |
|---|---|---|
| 发现 | /discover | 搜索、常用品类、内容推荐；首次进入不强迫选偏好 |
| 品类 | /categories | 24 类网格、全局搜索；只显示一级 |
| 品牌榜 | /categories/:slug/brands | 当前品类、档次说明、品牌列表、筛选、榜单依据 |
| 品牌详情 | /brands/:brandId?category=:id | 首屏定位、分节内容、来源、收藏/对比 |
| 搜索 | /search?q= | 品牌/商家两个结果区，输入防抖 300ms |
| 品牌对比 | /compare?category=:id&brands=:ids | 同类最多 3 个，属性纵向对齐，关键差异摘要 |
| 商家榜 | /merchant-board?category=:id | 品类切换、累计榜、商业标记、金额说明、最近更新时间 |
| 商家详情 | /merchants/:id?category=:id | 公开档案、各品类投入、店铺/直播/视频入口 |
| 外链确认 | bottom sheet | 平台名、目标域名、离站提示、主动作、复制/取消 |
| 登录 | /login?returnTo= | 手机号、验证码、协议、错误；保留原操作 |
| 我的 | /me | 收藏、关注、设置、商家中心 |
| 商家中心 | /merchant | 我的推广品牌、所属品类、累计投入；有链接才显示导流数据 |
| 商家编辑 | /merchant/profile | 名称与Logo；选填资料在折叠区，缺失不拦截 |
| 链接管理 | /merchant/links | 类型、平台、URL、视频封面、审核和有效状态 |
| 直播管理 | /merchant/live | 直播入口、自报状态、计划时间、30 分钟有效提示 |
| 打榜页 | /merchant/contribute?category=:id | 当前累计、输入金额、预计排名、规则、支付能力 |
| 订单与结果 | /merchant/orders/:id | 待支付/确认中/成功/失败/退款状态；查后端状态 |
| 账单与数据 | /merchant/analytics | 日期范围仅筛统计，不形成另一套排名 |
| 通知与反馈 | /notifications、/feedback | 站内消息、纠错进度 |
| 设置 | /settings | 字号、主题、隐私、注销、缓存 |

手机 Web 路由可直接刷新；原生使用应用链接进入同一业务页面。登录 returnTo 只允许内部白名单路由。
未发布/已删除对象展示 404 或已下线说明；无权对象返回 403，不能凭 URL 访问他人订单。

## 3. 关键页面线框

### 品牌榜
顶部：返回 + 耳机 + 搜索
说明：看懂声音之外的品牌表达
标签：品牌地位 / 定位说明
列表：01 品牌名｜高端级｜一句话定位
      大众辨识 较高  圈层认可 中等
      加入对比
底部：榜单依据与更新时间
商业入口：查看耳机商家榜（独立模块）

### 商家榜
顶部：大品类横向选择 + 全部品类
标题：耳机商家热度榜
紧邻说明：商业推广，按累计有效打榜投入排序；不定期清零的表述禁用，统一写“累计不清零”
前三：名次 / 品牌名 / Logo / ¥28,800；仅配置链接时显示店铺或直播入口
其余：列表条目，提供同等可点击信息，避免只看前三
说明展开：累计实付、累计退款、有效打榜额与最近变更
底部：商家入驻/管理入口（平台能力允许时）

默认不显示“月度”“本周”“距离下期”等元素。
公开显示的 ¥28,800 为示意；实际必须从后端账本获得。

### 商家详情
首屏：品牌名、Logo、名次与金额。只有填了介绍或链接才呈现扩展详情。
金额区：在当前品类有效打榜 ¥X，实付 ¥Y，已退 ¥Z，名次 #N。
内容：介绍、展示图片、门店信息等全部选填，不生成空分区。
有店铺或直播链接时，才显示相应主操作；全部未填时不出现底部链接操作条。
直播按钮标注平台；自报在线用“商家标记直播中”，附最近确认时间。

### 支付页
打榜首屏只展示三个必填项：品牌名、Logo、金额；当前大品类显示为只读上下文。已有档案追加时复用名称和Logo，只输入金额。\n明确文字“购买商家展示推广服务”，展示本次所属品类。
金额预设 ¥100 / ¥500 / ¥1,000 / ¥3,000 / 自定义；这些是可配置产品默认值，不是价格研究结论。
支付前说明：当前排名、预计排名仅供参考、同类竞争可能改变名次、累计额会扣除成功退款。
提交按钮防重复点击不代替后端幂等。
回到 App 只表示用户返回；先显示“支付结果确认中”，查到服务端成功才显示成功。

## 4. 视觉方向

风格：奢侈品杂志式排版 + 清晰目录导航。大量可读留白、克制强调色、品牌名称与排名数字形成视觉重点。
不用重玻璃模糊、大面积金色渐变、赌场式撒币特效、永动跑马灯。
内容消费端有编辑感；商家金额和后台数据采用清晰工具界面。

设计 token（Flutter ThemeExtension）：

| token | 浅色 | 深色 |
|---|---|---|
| background | #FAFAF9 | #121212 |
| surface | #FFFFFF | #1C1917 |
| textPrimary | #0C0A09 | #FAFAF9 |
| textSecondary | #475569 | #CBD5E1 |
| primary | #1C1917 | #FAFAF9 |
| onPrimary | #FFFFFF | #121212 |
| accent | #A16207 | #F4C56A |
| onAccent | #FFFFFF | #1C1917 |
| border | #D6D3D1 | #57534E |
| error | #B91C1C | #FCA5A5 |

状态必须配文字，不只靠颜色。正文和次级正文对比度至少 4.5:1，图形控件至少 3:1；交付脚本或检查报告验证实际组合。
标题 28/24/20，正文 16，辅助 14，榜位数字 32，金额 22–28；中文行高约 1.5。
中文使用平台清晰字体回退，可选有许可的思源宋体用于少量标题；拉丁标题可用 Cormorant，正文用系统无衬线。离线随包或自托管，不能依赖 Google Fonts 在线加载。
使用一套矢量图标；无图片使用文字占位，禁止编造品牌 Logo。

间距 4/8/12/16/24/32；手机左右 16–20；卡片圆角 12；主按钮高度至少 48。
金额使用等宽数字，完整显示到元；明细需要时显示两位小数；不以“2.8 万”替代应公开的精确投入金额。

## 5. Flutter 实施要求

- Riverpod 管理服务端状态，go_router 管理声明式路由，Dio 调用 API。
- feature-first 结构；共享 UI 与业务数据模型；支付、跳转、存储、分享、通知分平台适配。
- ThemeData + ColorScheme + ThemeExtension，禁止页面散落配色与资金算法。
- AsyncValue 明确 loading/data/empty/error；错误页有重试且保留筛选和滚动位置。
- ListView.builder/Slivers，稳定 key；不使用巨量 shrinkWrap 嵌套列表。
- 可变高度正文支持 TextScaler；禁止为了塞下金额全局关闭字号放大。
- 使用 PopScope 支持返回；从外部直播回到原列表位置；表单未保存时提示。
- dispose 控制器和订阅；异步返回后检查生命周期；Web 使用 kIsWeb/条件导入，不能全局导入 dart:io。
- 通知、相册、剪贴板等只在用户操作时请求；复制按钮不自动读取剪贴板。
- 安全存储抽象：原生凭据进系统安全存储；Web 优先 HttpOnly 会话 cookie，不能宣称 Flutter secure storage 在 Web 等价于钥匙串。

## 6. 多端适配与能力矩阵

| 环境 | 排名/内容 | 外链/直播 | 商家付款 |
|---|---|---|---|
| Android | 完整 | 系统浏览器、已验证 App Link，未安装时 HTTPS/复制 | 按发行渠道单独开通；默认走独立 Web 商家中心 |
| iOS | 完整 | Universal Links/系统浏览器，提供失败回退 | 默认关闭 App 内购买与引导；经审核的 IAP 或地区政策能力另行实现 |
| Flutter Web | 完整 | 用户点击打开 HTTPS；浏览器或宿主可能限制拉起 | 支持已开通 Web 支付；微信内浏览器和普通浏览器分别测试 |
| Windows/macOS/Linux | 自适应复用 | 默认系统浏览器和复制，不假定移动平台 SDK 可用 | 支持经过验证的 Web 收银台；不要求桌面 SDK 与手机相同 |

小于 600 逻辑像素：底部导航 + 单列；600–1023：导航栏 + 双列；1024 以上：侧导航 + 内容区最大宽度。
对比页小屏允许明确标识的横向表格滚动或逐项比较；普通页面不能整页横向溢出。
Web 分享预览与搜索抓取需要后端 HTML 元信息落地页，不能假定 Flutter Web 自动满足 SEO。

每个目标平台独立记录构建与真机测试结果。iOS/macOS 构建签名需要 macOS/Xcode；当前 Windows 设备不应被报告为已完成 iOS 打包。
